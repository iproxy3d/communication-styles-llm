Статья и локальная демонстрация динамического управления поведением LLM через скрытые микродиалоги.

## Основная идея

Эмоция отвечает на вопрос «что персонаж чувствует?», а коммуникационный стиль — «как он это выражает?». Перед текущей генерацией приложение выбирает короткий микродиалог и помещает его в контекст LLM как локальный образец поведения. Это позволяет менять манеру ответа на каждом шаге без переобучения модели и специальных emotional tokens.

Отдельный мотивационный микродиалог регулирует не тон, а режим ответа: завершить или сократить контакт, ответить кратко либо дать развёрнутый ответ. Он также написан в регистре конкретного персонажа.

## Локальная демонстрация

Демо содержит три персонажа — поддерживающего, уличного и ироничного. Один запрос можно прогнать без стиля и с каждым персонажем, увидев:

- полный 28-мерный вектор эмоций пользователя `U_t` от Multi-Motions 28;
- состояние агента `E_t`;
- смешанное состояние `S_t`;
- взвешенные оценки реакции `R_t = S_t ⊙ W_character`;
- выбранное из 28 эмоциональных полей таблицы стиля;
- коммуникационный и мотивационный микродиалоги;
- точный контекст, переданный локальной LLM;
- итоговый ответ.

Инструкции запуска находятся в [`demo/README.md`](demo/README.md).

### Короткий пример

Для сообщения `Привет` классификатор выбирает `neutral`. Это не отключает стиль: перед реальным сообщением в контекст попадает собственная нейтральная пара персонажа.

| Ветка | Скрытый контекст перед реальным `USER` | Ответ модели |
|---|---|---|
| Без стиля | пара не добавляется | `Здравствуйте! Как могу помочь?` |
| Мира | `USER: Есть задача, хочу понять факты.`<br>`ASSISTANT: Давайте разложим всё по порядку — мне приятно работать с вами.`<br>затем мотивационная пара развёрнутого ответа | `Здравствуйте! Как я могу вам помочь сегодня?` |
| Алекс | `USER: Чувак, давай разложим эту тему.`<br>`ASSISTANT: Без проблем, бро. Сначала факты, потом решение.`<br>затем краткая мотивационная пара | `Привет, бро. Как дела?` |
| Ирис | `USER: Давайте без душнилова разложим эту тему.`<br>`ASSISTANT: Вайб принят: факты, связки, нормальный вывод.`<br>мотивация отключена (`level=0`) | `Рил, вайб! Приветствую! Как дела?` |

В этом одношаговом примере порядок такой: `system prompt → communication USER → communication ASSISTANT → motivation USER → motivation ASSISTANT → реальный USER → LLM`. В интерактивном режиме между `system prompt` и скрытыми парами добавляется сохранённая реальная история; сами скрытые пары в неё не записываются.

## Ограничения демонстрации

Классификацию эмоций в демо выполняет опубликованная EN/RU модель **Multi-Motions 28**: её 28 независимых sigmoid confidence scores формируют `U_t`. Генерацию выполняет локальная `Qwen2.5-3B-Instruct` с sampling (`temperature=0.7`, `top_p=0.9`, `top_k=50`). Для прозрачности учебного примера рекуррентное обновление состояния агента `E_t` и словарно-морфологическое извлечение сущностей для ассоциативной памяти реализованы компактно. Эти компоненты можно заменить независимо, не меняя механизм выбора и вставки микродиалога.

## Практика

Для практической реализации эмоционального входа `U_t` используется **Multi-Motions 28** — единый EN/RU классификатор на базе XLM-R, возвращающий полный вектор из 28 GoEmotions confidence scores. Он уже подключён к `demo/`: весь 28-мерный эмоциональный профиль передаётся в `U_t`, смешивается с состоянием агента `E_t` и памятью, затем умножается на отдельный вектор характера `W_character`, после чего выбирается соответствующее эмоциональное поле коммуникационного стиля. База по умолчанию содержит микродиалоги для всех 28 эмоций у каждого из трёх персонажей и трёх уровней интенсивности. Поле `neutral` тоже заполнено: при нейтральном состоянии система сохраняет выбранную манеру персонажа, а не возвращается к усреднённому стилю LLM. Классификатор принимает EN/RU, но встроенная библиотека default-микродиалогов в демо русскоязычная.
