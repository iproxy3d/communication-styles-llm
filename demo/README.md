# Локальная демонстрация коммуникационных стилей и ассоциативной памяти

Это минимальный исполняемый пример к статье. Он показывает четыре независимые части архитектуры:

1. эмоциональное состояние пользователя `U_t`;
2. текущее состояние агента `E_t`;
3. ассоциативную эмоциональную память `A_t`;
4. динамические коммуникационные и мотивационные микродиалоги, которые добавляются непосредственно перед текущим запросом.

Ответ генерирует маленькая локальная LLM. После однократной загрузки весов облачный API не нужен.

## Что изменилось в версии 1.2

В предыдущем демо ассоциативной памяти не было. Теперь она реализована полностью в минимальном виде:

```text
текст пользователя
    ↓
выделение и нормализация сущностей
    ↓
поиск ассоциаций в SQLite
    ↓
A_t
    ↓
S_t = alpha·U_t + (1-alpha)·E_t + beta·A_t
    ↓
выбор коммуникационного микродиалога
    ↓
мотивационный микродиалог
    ↓
локальная LLM
    ↓
ответ
    ↓
обновление A(entity) текущим S_t
```

Ассоциации принадлежат конкретному персонажу: Мира, Алекс и Ирис могут накопить разные эмоциональные связи с одной и той же сущностью.

## Формулы

Базовое состояние без памяти:

```text
S_base = alpha · U_t + (1 − alpha) · E_t
```

С ассоциативной памятью:

```text
S_t = alpha · U_t + (1 − alpha) · E_t + beta · A_t
```

- `U_t` — эмоции в текущем сообщении пользователя;
- `E_t` — состояние агента перед ответом;
- `A_t` — агрегированный эмоциональный сигнал найденных ассоциаций;
- `alpha` — ориентация стиля на текущего собеседника;
- `beta` — сила влияния памяти.

После ответа ассоциация каждой найденной сущности обновляется:

```text
A_{t+1}(q) = (1 − eta) · A_t(q) + eta · S_t
```

В этом учебном демо в память записывается именно итоговое `S_t`, использованное для выбора коммуникационного стиля. Это сделано намеренно, чтобы наглядно показать накопление эмоционального контекста взаимодействия.

## Как выделяются сущности

Baseline специально остаётся прозрачным и не требует отдельной NER-модели.

В SQLite хранится небольшой словарь известных сущностей, например:

```text
самолет
рейс
аэропорт
иванов
париж
билет
```

Текст нормализуется через `pymorphy3`, поэтому формы вроде:

```text
Иванову    -> иванов
Ивановым   -> иванов
самолётами -> самолет
самолёте   -> самолет
```

сводятся к одному ключу памяти.

`style_demo/association.py` содержит отдельный `EntityExtractor`, поэтому позднее его можно заменить на BERT/RoBERTa NER, Natasha, spaCy или другой extractor, не меняя остальную архитектуру памяти.

Если `pymorphy3` по какой-либо причине отсутствует, код имеет маленький fallback для нескольких демонстрационных форм. Для нормальной работы следует устанавливать зависимости из `requirements.txt`.

## Что хранится в SQLite

Кроме прежних таблиц добавлены:

### `memory_entities`

Словарь канонических сущностей и псевдонимов.

### `associative_memory`

Для пары:

```text
(character_id, entity_id)
```

хранятся:

- эмоциональный вектор;
- количество встреч `encounters`.

Пример:

```text
Мира / самолет
neutral=0.19 fear=0.46 anger=0.00 annoyance=0.00 joy=0.00
encounters=5
```

Значения памяти специально не нормализуются после каждой записи. Поэтому новая ассоциация сначала слаба, а повторные встречи постепенно увеличивают её влияние.

## Трассировка

Для каждого ответа программа показывает:

```text
U_t        — состояние пользователя
E_t        — состояние агента
S_base     — состояние без памяти
A_t        — ассоциативный сигнал
S_t        — итоговое состояние выбора стиля
entities   — найденные и нормализованные сущности
style      — выбранный коммуникационный стиль
microdialogue
motivation microdialogue
answer
memory update
```

Таким образом видно не только итоговый ответ, но и причину изменения коммуникационного поведения.

## Самый наглядный тест памяти

Можно проверить весь механизм без загрузки LLM:

```bash
python app.py --backend echo --memory-demo
```

Сценарий автоматически:

1. очищает память выбранного персонажа;
2. несколько раз предъявляет эмоционально отрицательные сообщения о самолёте;
3. формирует ассоциацию `самолет -> fear`;
4. затем подаёт нейтральное сообщение:

```text
Завтра летим на самолете в Париж.
```

У нейтральной фразы `U_t` почти нейтрален, но `A_t` уже содержит страх, поэтому итоговый `S_t` сдвигается памятью.

## Ручной сценарий

```bash
python app.py --backend echo --reset-memory --character Мира

python app.py --backend echo --character Мира \
  --message "Я очень боюсь самолета, мне страшно летать"

python app.py --backend echo --character Мира \
  --message "Самолетами я летать боюсь, каждый рейс вызывает тревогу"

python app.py --backend echo --show-memory --character Мира

python app.py --backend echo --character Мира \
  --message "Завтра летим на самолете в Париж"
```

Одноразовые вызовы `--message` сохраняют ассоциации в `db.sqlite3`, даже если реальная история разговора между процессами не сохраняется.

## Другие команды

```bash
# Интерактивный диалог: память обучается автоматически
python app.py --character Мира

# Посмотреть память персонажа
python app.py --show-memory --character Мира

# Очистить только память персонажа
python app.py --reset-memory --character Мира

# Полностью выключить память на текущем вызове
python app.py --no-memory --message "Завтра летим на самолете"

# Изменить силу памяти beta
python app.py --memory-beta 0.6 --message "Завтра летим на самолете"

# Изменить скорость обучения eta
python app.py --memory-eta 0.1 --message "Я боюсь самолета"
```

## Порядок формирования контекста LLM

Механизм микродиалогов не изменился:

```text
system prompt
→ реальная история диалога
→ коммуникационный микродиалог
→ мотивационный микродиалог
→ текущее сообщение пользователя
→ локальная LLM
```

Ассоциативная память не вставляется в контекст как факт. Она влияет на `S_t`, затем на выбор коммуникационного микродиалога. Поэтому смысловая память и управляющий стиль не смешиваются.

## Состояние агента

`E_t` по-прежнему обновляется простым учебным рекуррентным правилом:

```text
E_{t+1} = 0.8 · E_t + 0.2 · U_t
```

Это не полноценная эмоциональная модель агента, а прозрачная заглушка. Ассоциативная память при этом уже является persistent: она хранится в SQLite между запусками.

## Структура проекта

- `app.py` — CLI, сравнение персонажей, память и трассировка;
- `style_demo/db.py` — SQLite, стили, персонажи и ассоциации;
- `style_demo/emotion.py` — `U_t`, `E_t`, `S_base`, `S_t`;
- `style_demo/association.py` — нормализация сущностей и вычисление `A_t`;
- `style_demo/engine.py` — общий цикл памяти, стиля и микродиалогов;
- `style_demo/local_llm.py` — локальная генерация через Transformers;
- `download_model.py` — загрузка весов;
- `tests/` — тесты микродиалогов и ассоциативной памяти.

## Что намеренно не входит в baseline

Чтобы пример оставался объяснимым, здесь пока нет:

- BERT/RoBERTa NER;
- контекстных ассоциаций `(Entity, Context) -> Emotion`;
- embedding retrieval сущностей;
- затухания долговременных ассоциаций;
- TTS;
- веб-сервера;
- полной эмоциональной модели персонажа.

Все эти компоненты можно добавить независимо. Основной интерфейс уже отделён: extractor получает текст и возвращает канонические сущности, память возвращает `A_t`, а коммуникационный слой использует этот сигнал при выборе микродиалога.
