# Локальная демонстрация коммуникационных стилей

[← Вернуться к статье](../index.html)

Это минимальный исполняемый пример к статье. Он показывает, как выбрать коммуникационный стиль по эмоциональному состоянию, превратить его в скрытый микродиалог и вставить этот микродиалог непосредственно перед текущим сообщением пользователя. Ответ генерирует маленькая LLM на компьютере пользователя; облачный API не используется.

## Что видно при запуске

Один и тот же запрос сравнивается в четырёх вариантах:

1. без управляющих микродиалогов;
2. персонаж **Мира** — поддерживающий стиль и высокая мотивация;
3. персонаж **Алекс** — формальный стиль и слабая мотивация;
4. персонаж **Ирис** — мягко-ироничный стиль и слабая мотивация.

Программа печатает не только ответ, но и всю трассировку: `U_t`, `E_t`, `S_t`, выбранную эмоцию, оба скрытых микродиалога и точный список сообщений, переданный модели.

## Быстрый запуск

Нужен Python 3.10–3.12. Первый шаг требует интернета только для однократной загрузки открытых весов модели. После загрузки генерация выполняется локально.

### Windows

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python download_model.py
.venv\Scripts\python app.py --compare --show-context
```

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python download_model.py
.venv/bin/python app.py --compare --show-context
```

После настройки повторный запуск выполняется последней командой. Модель `Qwen/Qwen2.5-0.5B-Instruct` выбрана как небольшая instruct-модель с поддержкой русского языка. На CPU первый ответ может формироваться заметно дольше последующих.

## Другие режимы

```bash
# Одна реплика конкретному персонажу
python app.py --character Ирис --message "Опять всё сломалось"

# Интерактивный диалог с переопределённой мотивацией
python app.py --character Мира --motivation 0

# Проверить конвейер без загрузки весов (это не содержательная генерация)
python app.py --backend echo --compare --show-context
```

Уровни мотивации: `-1` — минимальная вовлечённость, `0` — микродиалог отсутствует, `1` — краткий полноценный ответ, `2` — развитие разговора и уместный следующий шаг.

## Что хранится в `db.sqlite3`

- `communication_styles`: имя стиля и строковые поля `neutral`, `fear`, `anger`, `annoyance`, `joy`. Каждое поле содержит JSON-набор микродиалогов трёх уровней интенсивности.
- `characters`: системное описание персонажа, ссылка на стиль, `alpha`, интенсивность и уровень мотивации.
- `motivation_styles`: четыре самостоятельных мотивационных микродиалога.

Пять эмоций оставлены намеренно, чтобы таблицу можно было понять глазами. В прикладной системе набор полей можно расширить до полного пространства эмоций статьи.

## Порядок формирования контекста

```text
system prompt
→ реальная история диалога
→ коммуникационный микродиалог
→ мотивационный микродиалог
→ текущее сообщение пользователя
→ локальная LLM
```

Скрытые вставки создаются заново для текущего ответа и не записываются в реальную историю. Благодаря этому они остаются свежим локальным сигналом, но не засоряют историю искусственными репликами.

## Формула демонстрации

```text
S_t = alpha · U_t + (1 − alpha) · E_t
```

- `U_t` — эмоции в текущей реплике пользователя;
- `E_t` — состояние агента перед ответом;
- `alpha` — чувствительность к текущей реплике: чем выше значение, тем быстрее стиль реагирует на пользователя;
- `S_t` — состояние, по которому выбирается поле таблицы стилей.

Детектор эмоций здесь специально сделан прозрачным и словарным. Простое рекуррентное обновление `E_t` также является учебной заглушкой. В рабочей системе их заменяют классификатором и собственной эмоциональной моделью, не меняя интерфейс селектора или способ вставки микродиалога.

## Структура проекта

- `app.py` — CLI, сравнение персонажей и трассировка;
- `style_demo/db.py` — схема SQLite и примеры строковых полей;
- `style_demo/emotion.py` — учебные `U_t`, `E_t`, `S_t`;
- `style_demo/engine.py` — выбор и вставка микродиалогов;
- `style_demo/local_llm.py` — локальная генерация через Transformers;
- `download_model.py` — однократная загрузка весов;
- `tests/` — проверки порядка вставки и границ истории.

## Проверка

```bash
python -m unittest discover -s tests -v
# Также поддерживается прямой запуск:
python tests/test_demo.py
```

Демонстрация не реализует TTS, веб-сервер, ассоциативную память и полную эмоциональную систему: эти части не нужны, чтобы увидеть и повторить основной механизм коммуникационных и мотивационных микродиалогов.
