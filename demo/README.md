# Локальная демонстрация коммуникационных стилей, Multi-Motions 28 и ассоциативной памяти

Это исполняемый пример к статье «Коммуникационные стили в агентских системах». Он показывает полный минимальный контур:

1. реальный EN/RU классификатор эмоций **Multi-Motions 28** формирует `U_t`;
2. рекуррентное состояние агента задаёт `E_t`;
3. ассоциативная эмоциональная память возвращает `A_t`;
4. из 28-мерного состояния выбирается эмоциональное поле коммуникационного стиля;
5. из SQLite берётся скрытый коммуникационный микродиалог;
6. после него добавляется мотивационный микродиалог;
7. небольшая локальная `Qwen2.5-0.5B-Instruct` генерирует реальный ответ.

После однократной загрузки весов внешние LLM/API для выполнения демо не нужны.

## Модели

### Эмоции пользователя

Используется опубликованная модель:

- **Hugging Face:** https://huggingface.co/proxy3d/multi-motions-28
- **описание, обучение и бенчмарки:** https://huggingface.co/spaces/proxy3d/multi-motions-28-article

`proxy3d/multi-motions-28` — XLM-R классификатор для английского и русского текста. На выходе он даёт 28 независимых sigmoid confidence scores:

```text
admiration, amusement, anger, annoyance, approval, caring,
confusion, curiosity, desire, disappointment, disapproval, disgust,
embarrassment, excitement, fear, gratitude, grief, joy, love,
nervousness, optimism, pride, realization, relief, remorse,
sadness, surprise, neutral
```

Это multi-label выход. Значения **не нормализуются до суммы 1**: несколько эмоций могут одновременно иметь высокие scores.

### Генерация ответа

Для локального ответа используется:

```text
Qwen/Qwen2.5-0.5B-Instruct
```

Классификатор и генеративная модель скачиваются в `demo/models/` один раз.

## Эмоциональное пространство демо

Весь коммуникационный контур использует одно и то же 28-мерное пространство эмоций Multi-Motions 28:

- `U_t` — 28 независимых sigmoid confidence scores классификатора;
- `E_t` — 28-мерное внутреннее состояние агента;
- `A_t` — 28-мерный сигнал ассоциативной памяти;
- `S_t` — 28-мерное состояние, по которому выбирается эмоциональное поле коммуникационного стиля;
- `R_t = S_t ⊙ W_character` — оценки после применения весов характера;
- SQLite содержит поля для всех 28 эмоций у каждого из трёх персонажей;
- для каждой пары `стиль × эмоция` есть три уровня интенсивности `0/1/2`;
- каждый коммуникационный вариант хранится как законченная пара `USER → ASSISTANT`.
- поле `neutral` также всегда содержит полноценный микродиалог для каждого стиля: нейтральность отключает эмоциональное усиление, но не сам коммуникационный стиль.

Unit-тесты используют маленький deterministic test double классификатора, поэтому для тестов не требуется скачивать веса модели.

## Три персонажа и их таблицы стиля

В базе по умолчанию есть три персонажа:

| Персонаж | Стиль | Поведение |
|---|---|---|
| **Мира** | `supportive` | тёплый, спокойный, поддерживающий |
| **Алекс** | `formal` | сдержанный, точный, деловой |
| **Ирис** | `ironic` | мягкая ирония без изменения фактов и без насмешки над уязвимостью пользователя |

Для каждого стиля заполнены все 28 полей классификатора. Например, одна и та же `nervousness` при средней интенсивности хранится так:

```text
Мира / supportive
USER: Я нервничаю перед тем, что будет дальше.
AI:   Понимаю, вы напряжены. Разберём ближайший шаг.

Алекс / formal
USER: Я нервничаю перед тем, что будет дальше.
AI:   Напряжение понятно. Сосредоточимся на действиях, которые можно контролировать.

Ирис / ironic
USER: Я нервничаю перед тем, что будет дальше.
AI:   Похоже, внутренний сигнал тревоги работает сверхурочно. Давайте дадим ему один понятный следующий шаг.
```

Для чувствительных состояний стиль не должен превращаться в карикатуру. Например, у Ирис поле `grief` намеренно ослабляет иронию:

```text
USER: Я всё ещё не могу принять, что это произошло.
AI:   Это тяжёлая потеря. Ирония сейчас ни к чему — можно просто не торопиться.
```

Полный набор находится в `style_demo/default_styles.py` и при создании базы записывается в `communication_styles`.

Классификатор принимает английский и русский текст, но встроенные default-микродиалоги этого демо русскоязычные. Поэтому EN/RU относится к входному классификатору; полноценная англоязычная библиотека скрытых примеров в этот архив не включена.

## Эмоциональное состояние и память

Базовое коммуникационное состояние:

```text
S_base = alpha · U_t + (1 − alpha) · E_t
```

С ассоциативной памятью:

```text
S_t = alpha · U_t + (1 − alpha) · E_t + beta · A_t
```

где:

- `U_t` — 28 sigmoid scores Multi-Motions 28 для текущего сообщения;
- `E_t` — 28-мерное состояние агента перед ответом;
- `A_t` — 28-мерный агрегированный сигнал ассоциативной памяти;
- `alpha` — ориентация коммуникации на текущего собеседника;
- `beta` — сила влияния памяти.

`U_t` и `E_t` не являются categorical distributions. После смешения демо только ограничивает координаты диапазоном `[0,1]`, но не делит их на сумму всех эмоций.

Состояние агента обновляется простым учебным правилом:

```text
E_{t+1} = 0.8 · E_t + 0.2 · U_t
```

Это прозрачная учебная модель внутренней эмоциональной динамики персонажа. Вход `U_t` при этом формируется обученным классификатором Multi-Motions 28.

После ответа найденные ассоциации обновляются:

```text
A_{t+1}(q) = A_t(q) + eta · (E_t − A_t(q))
A ← gamma · A
```

В коде обновление получает именно `E_t`, то есть состояние агента перед текущим ответом, а не смешанное состояние выбора `S_t`. После EMA-обновления отдельный шаг `A ← gamma · A` применяется ко всем сохранённым ассоциациям, а каждая координата ограничивается диапазоном `[0,1]`. `gamma` задаётся параметром `--memory-gamma` и по умолчанию равен `1.0`.

## Как выделяются сущности

Ассоциативная часть демонстрации намеренно реализована компактно. В SQLite хранится небольшой словарь известных сущностей, например:

```text
самолет
рейс
аэропорт
иванов
париж
билет
```

Текст нормализуется через `pymorphy3`, поэтому формы вроде:

```text
Иванову    -> иванов
Ивановым   -> иванов
самолётами -> самолет
самолёте   -> самолет
```

сводятся к одному ключу памяти. `style_demo/association.py` отделён от остальной системы, поэтому его можно заменить полноценным NER без изменения классификатора, памяти или выбора стиля.

## Что хранится в SQLite

### `communication_styles`

Три строки стилей и 28 эмоциональных колонок. Каждая ячейка хранит JSON с тремя уровнями интенсивности:

```text
0 -> USER + ASSISTANT
1 -> USER + ASSISTANT
2 -> USER + ASSISTANT
```

### `characters`

Связь персонажа со стилем, `alpha`, интенсивностью, мотивацией и начальным `E_t`.

### `character_weights`

Отдельная таблица 28 координат `W_character` для каждого персонажа. В текущем архиве числовые веса характера не заданы в таблице микродиалогов, поэтому при инициализации используются нейтральные значения `1.0`; их можно заменить в SQLite без изменения текстовой библиотеки `communication_styles`. Нулевой вес делает координату недоступной, а значение больше `1.0` усиливает её перед выбором максимальной реакции.

### `motivation_styles`

Независимый мотивационный микродиалог уровней `-1, 0, 1, 2`. Для уровней `-1/1/2` он хранится как обычная пара `USER → ASSISTANT`; уровень `0` ничего не добавляет. Это сохраняет естественное чередование ролей в полном chat-контексте.

### `memory_entities`

Словарь канонических сущностей и псевдонимов.

### `associative_memory`

Для пары `(character_id, entity_id)` хранится 28-мерный эмоциональный вектор и число встреч `encounters`.

## Порядок формирования контекста LLM

```text
system prompt
→ реальная история диалога
→ коммуникационный микродиалог выбранной эмоции
→ мотивационный микродиалог
→ текущее сообщение пользователя
→ локальная LLM
```

Скрытые микродиалоги не записываются в реальную историю. Ассоциативная память тоже не вставляется в prompt как факт: она только влияет на `S_t` и через него — на выбор стиля.

## Трассировка

Для каждого ответа программа показывает:

```text
U_t        — 28 scores Multi-Motions 28
E_t        — состояние агента
S_base     — состояние без памяти
A_t        — ассоциативный сигнал
S_t        — итоговое состояние выбора стиля
R_t        — S_t, умноженное на W_character
entities   — найденные сущности
style      — стиль персонажа
emotion    — выбранная координата из 28
communication microdialogue
motivation microdialogue
answer
memory update
```

Чтобы вывод не занимал несколько экранов, CLI показывает наиболее сильные координаты и помечает общую размерность `(28 dims)`.

## Быстрый запуск

Нужен Python 3.10–3.12.

### Windows

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python download_model.py
.venv\Scripts\python app.py --compare --show-context
```

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python download_model.py
.venv/bin/python app.py --compare --show-context
```

`download_model.py` загружает обе модели:

```text
Qwen/Qwen2.5-0.5B-Instruct
proxy3d/multi-motions-28
```

После этого inference выполняется из локальных директорий `demo/models/...`.

## Сравнение трёх персонажей

```bash
python app.py --compare --message "Я боюсь опоздать на рейс. Что мне делать?" --show-context
```

Один и тот же `U_t` проходит через baseline и три полные конфигурации персонажей. В режиме `--compare` ассоциативная память отключена для всех ветвей, а baseline использует нейтральный system prompt. Это сравнение конфигураций продукта, а не чистый причинный A/B-тест, в котором менялось бы только наличие микродиалога: у персонажей различаются system prompt, `alpha`, стиль, `W_character` и мотивация.

## Интерактивный режим

```bash
python app.py --character Мира
python app.py --character Алекс
python app.py --character Ирис
```

## Демонстрация памяти

Можно не загружать Qwen и использовать test backend для генерации:

```bash
python app.py --backend echo --memory-demo
```

Важно: `--backend echo` заменяет только генеративную LLM. **Multi-Motions 28 всё равно используется для `U_t`**, поэтому перед первым запуском `download_model.py` нужен и для этого режима.

Сценарий:

1. очищает память выбранного персонажа;
2. несколько раз подаёт сообщения о страхе полёта;
3. записывает эмоциональную ассоциацию с `самолет`;
4. затем подаёт более нейтральное сообщение:

```text
Завтра летим на самолете в Париж.
```

Сравните `S_base` и `S_t`: если память накопила fear/nervousness, `A_t` сдвигает итоговое состояние даже при более спокойном текущем `U_t`.

## Структура проекта

- `app.py` — CLI, сравнение персонажей, память и трассировка;
- `style_demo/emotion_classifier.py` — локальная обёртка над `proxy3d/multi-motions-28`;
- `style_demo/emotion.py` — 28 координат, `E_t`, `S_base`, `S_t`;
- `style_demo/default_styles.py` — 28 × 3 стиля × 3 интенсивности коммуникационных микродиалогов;
- `style_demo/db.py` — SQLite, стили, персонажи, W_character и ассоциации;
- `style_demo/association.py` — нормализация сущностей и вычисление `A_t`;
- `style_demo/engine.py` — общий цикл classifier → memory → style → microdialogue → LLM;
- `style_demo/local_llm.py` — локальная генерация через Transformers;
- `download_model.py` — однократная загрузка обеих моделей;
- `tests/` — offline unit-тесты без скачивания весов.

## Что намеренно упрощено

Чтобы пример оставался читаемым, здесь пока нет:

- полноценного NER вместо словаря + `pymorphy3`;
- контекстных ассоциаций `(Entity, Context) -> Emotion`;
- embedding retrieval сущностей;
- полноценной модели динамики `E_t`;
- TTS;
- веб-сервера.

Классификацию пользовательских эмоций выполняет опубликованная **Multi-Motions 28** непосредственно; перечисленные выше упрощения относятся к другим компонентам учебного контура.
